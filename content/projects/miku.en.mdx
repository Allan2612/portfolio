## Context

Miku Assistant is a voice assistant for Windows, with an animated character that lives on the desktop. You call it with a keyboard shortcut or a wake word and talk to it: it opens apps, switches windows and tabs, controls music and volume, sets timers and reminders, takes notes and answers questions. Before doing anything destructive, it asks.

I built it on my own as an open-source project, around two goals: answer in **under three seconds**, and use **almost no resources while idle**, because it runs on a PC that is also used for everything else.

## What I did

- **A desktop app** with a Live2D character, lip sync and subtitles, in a transparent window (Tauri and TypeScript).
- **A Python core** that listens, transcribes speech on the CPU with Whisper and uses Gemini as an agent that knows what is open on the PC.
- **The character’s own voice**, converted on the GPU only while it is needed; when idle, video memory goes back to zero.
- **Safety by design:** the assistant can only use a closed list of tools, never runs arbitrary commands, and asks before anything destructive.
- **An optional browser extension** so it knows which tabs are open and can act on them.

## Result

- **Designed to respond in under 3 seconds** after activation, by loading the voice while the user is still speaking.
- **Releases the GPU when idle**: 0 MB of video memory, with the voice back in a few seconds when needed.
- Open source under the MIT license, with architecture notes, a tool reference, a changelog and its own audit plan.

## Technical decisions

### How it works

Two processes talk over a local WebSocket, plus a GPU worker for the voice and an optional browser extension:

- **The app** (Tauri v2 and TypeScript): a transparent window with the Live2D avatar, animations, lip sync and subtitles.
- **The core** (Python, asyncio): activation, microphone and voice detection, speech-to-text, the agent loop with Gemini, PC tools and text-to-speech.
- **The voice worker:** converts the base voice into the character’s voice on the GPU, in its own process.
- **The browser extension** (Opera): exposes open tabs and search results to the core.

A request goes like this:

1. It is activated with a keyboard shortcut or a wake word. In parallel, Whisper checks the wake-word audio, so a clearly false activation is dropped without spending a request.
2. At that moment the voice worker starts loading, **while the user is still speaking**.
3. Recording stops on silence and Whisper transcribes on the CPU. Unambiguous commands (volume, pause, timers, notes) are handled locally, without the model.
4. Everything else goes to Gemini together with the **current state of the PC**: open windows and tabs, each with a number, the volume, reminders and to-dos. Gemini acts as an agent: it calls tools, sees their results, and answers or takes another step. Destructive actions ask for confirmation.
5. edge-tts produces the base voice and RVC converts it.
6. The app plays it with lip sync, an expression and a subtitle, and keeps listening for a few seconds in case the conversation continues.
7. After a while without use, the avatar hides and stops rendering. Later the voice worker is killed and GPU memory goes back to zero, while a standby worker waits in RAM with its libraries loaded, so the voice comes back in a few seconds.

### No GPU framework in the main process

On Windows, initializing CUDA leaves a few hundred megabytes resident that are never given back. So the main process never loads PyTorch: the voice runs in a subprocess that can be killed, and Whisper runs on the CPU with 8-bit weights and stays in RAM. Killing the process is the only reliable way to free that GPU memory.

### A closed list of tools

The model can only call tools from a registered list: apps, windows, files, media, notes, memory, routines, system settings, timers and the web. It never runs arbitrary shell commands, and anything destructive needs the user’s confirmation. That limits what prompt injection can do: nothing destructive runs without confirmation. A web page could still steer a harmless tool, such as opening a link or saving a note, but if it tells the assistant to “close everything”, the worst it can do is ask.

### Windows and tabs as numbered objects

The model sees a numbered list of what is open and acts on a specific number, instead of guessing from a title or simulating key presses. “Close the second tab” becomes a precise call, not a fragile shortcut.

### Only unambiguous commands skip the model

Volume, media, timers and notes are matched locally and run immediately, without a round trip to the model. Anything that depends on what is open goes to Gemini with the PC state, because a local rule would guess wrong.

### One voice, and it never hangs

The character has a single voice. If the voice worker is still loading, the answer waits; if it fails, the answer comes as a subtitle only, never in a different voice. No component can leave the assistant stuck.

### No UI framework

The app is plain TypeScript with Vite. The WebView already costs memory; a UI framework would add more for a window that shows one character.
